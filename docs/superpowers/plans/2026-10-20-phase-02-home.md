# Phase 2: Home Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the first impression, at production polish. It answers *what, why, when, where and which sectors* above and just below the fold, in EN, PT-BR and BN, using BBCCI's real photography and sourced figures.

**Architecture:**

- **Data:** CMS-ready content models with translatable JSON fields and idempotent seeders: `Stat`, `Milestone`, `Sector` (base fields; Phase 3 extends it), `Testimonial`, `Video`, `Partner`. The console (Release B) edits them later without code changes.
- **Copy:** page copy lives in `lang/{locale}/home.php`.
- **Rendering:** `HomeController` builds a `HomePage` view model. The home view is split into section partials under `resources/views/home/` (`hero`, `countdown`, `paths`, `why`, `routes`, `sectors`, `where`, `timeline`, `highlights`, `partners`, `cta`).
- **Interactivity:** Alpine for the countdown, dual clocks, timeline scroller and YouTube facade.
- **Newsletter:** a Livewire 4 component with double opt-in.
- **Trade-route map:** a static dotted-world SVG generated once from Natural Earth data and committed. The animated routes are an inline SVG overlay. There is no runtime map library, so the static fallback is the same artwork.

**Spec:** §5A Home, §5O consents, §5P budgets, §6. **Master plan:** Phase 2 (Release A order).

## Global Constraints

- Phase 0 and Phase 1 constraints apply. Event facts come from `Edition`, `Venue` and `GeneralSettings`; figures come from `Stat` rows, each with a source and an as-of date (spec §4 note).
- **Every figure on the page shows its source** (a short form such as "ComexStat, 2025" or "EPB, FY2025-26"):

  | Figure | Value |
  |---|---|
  | Bilateral trade 2025 | Brazil → Bangladesh US$2.72 bn; Bangladesh → Brazil US$281.8 m (Trading Economics/UN Comtrade, CY2025) |
  | Bangladesh exports to Brazil | US$215 m, +14.6% (EPB, FY2025-26) |
  | Apparel share of Bangladesh → Brazil | ~90% (Trading Economics, CY2025) |
  | Brazil's place among clothing suppliers | Bangladesh is #2 (ComexStat, 2018–2025) |
  | Brazil's cotton share for Bangladesh | ~25% (USDA FAS, MY2024/25) |
  | Brazil's consumers | 213 m (World Bank, 2024) |
  | Diplomatic relations | since 1972; Brazil was the first Latin American country to recognise Bangladesh |

- **Two-way trade (spec §4):** the page addresses Bangladeshi exporters *and* Bangladeshi importers who meet Brazilian suppliers.
- **YouTube:** nothing loads from YouTube until the visitor presses play (facade). This is the consent moment, and the copy says so.
- **Newsletter:**
  - Email, plus an explicit unticked consent checkbox (versioned text).
  - A signed confirmation link expiring in 7 days, a confirmation page, and an unsubscribe link.
  - No marketing email before confirmation.
  - Honeypot field and rate limit (5 per minute per IP).
- **Budgets:**
  - The hero image is eager and `fetchpriority=high`; everything else is lazy.
  - No new JS dependencies at runtime.
  - The map SVG is an external cached file (≤ 80 KB raw).
- **Dev-only dependencies:** `world-atlas` and `topojson-client`, used by `resources/js/build/world-dots.mjs` to generate `public/img/world-dots.svg`.

### Task 1: Content models and seeders

**Files:**
- Via `make:model -mfs`: `Stat`, `Milestone`, `Sector`, `Testimonial`, `Video`, `Partner`, plus enum `PartnerRole`.
- Seeders: `HomeContentSeeder` (calls the per-model seeders), called from `DatabaseSeeder`.
- Test: `tests/Feature/Models/HomeContentTest.php`

**Schema** (translatable fields are `json`; every table has `sort` unsignedSmallInteger default 0 and timestamps):

| Model | Columns |
|---|---|
| `Stat` | `key` unique string; `value` decimal(14,2); `decimals` tinyint; `prefix` nullable string; `suffix` json (translatable, nullable); `label` json; `source` string; `as_of` string; `placement` string (default `home`) |
| `Milestone` | `happened_on` date; `date_label` json (nullable, e.g. "Mar 2027"); `title` json; `body` json; `image` nullable string (image key); `edition_id` nullable FK |
| `Sector` | `slug` json (translatable: en/bn English, pt translated); `name` json; `summary` json; `icon` string; `image` nullable string; `figure_value` decimal(14,2) nullable; `figure_decimals` tinyint; `figure_prefix`, `figure_suffix` (json); `figure_label` json; `figure_source` nullable string |
| `Testimonial` | `quote` json; `person` string; `role` json; `image` nullable string; `edition_id` nullable FK |
| `Video` | `youtube_id` string unique; `title` json; `speaker` nullable string; `edition_id` nullable FK |
| `Partner` | `name` json; `role` (`PartnerRole`: organiser, supporter, institutional, media); `url` nullable; `logo` nullable image key; `edition_id` nullable FK |

**Decisions:**
- Each model has `use HasTranslations` and an `ordered()` scope (`orderBy('sort')`).
- `Sector::localizedSlug(string $locale): string` returns the slug for that locale, falling back to en.
- **Sectors** (en name / pt slug / icon):
  - Garments / `vestuario` / shirt
  - Home & technical textiles / `texteis` / layers
  - Pharmaceuticals / `farmaceuticos` / pill
  - Leather & footwear / `couro-e-calcados` / footprints
  - Jute & jute goods / `juta` / leaf
  - Agro-food & seafood / `agroalimentos` / wheat
  - Handicrafts & décor / `artesanato` / palette
  - Plastics & toys / `plasticos-e-brinquedos` / puzzle
  - ICT & software / `tic` / cpu
  - en/bn slugs: `garments`, `textiles`, `pharmaceuticals`, `leather-footwear`, `jute`, `agro-food`, `handicrafts`, `plastics-toys`, `ict`.
- Each sector has one headline figure with its source (taken from docs/research/02 §3 and 03 §A.5).
- **Content source:** the copy in all three languages is written for this phase from `docs/research/01` and `03`. PT and BN are AI-drafted and marked for client review in the ledger (spec §11).

- **Side panel** with what each way trades:
  - BD → BR: apparel, jute, leather, home textiles, pharma
  - BR → BD: sugar, cotton, cereals, soy, edible oils

### Task 7: Newsletter double opt-in and CTA band

**Files:**
- `make:model NewsletterSubscription -mf`
- `app/Livewire/NewsletterSignup.php` with its view
- `app/Mail/ConfirmNewsletterSubscription.php` and a markdown mail
- `app/Http/Controllers/NewsletterController.php` (`confirm`, `unsubscribe`)
- Routes inside `Route::localized`: `newsletter.confirm` (signed), `newsletter.unsubscribe` (signed)
- `resources/views/newsletter/{confirmed,expired,unsubscribed}.blade.php`
- `resources/views/home/cta.blade.php`

**Schema:** `email` unique; `locale`; `consent_version`; `consented_at`; `consent_ip`; `confirmed_at` nullable; `unsubscribed_at` nullable.

**Decisions:**
- The Livewire component validates the email and the required consent box.
- **Rate limit:** `RateLimiter` key per IP, 5 per minute.
- A honeypot property (`website`) must be empty.
- A new email creates an unconfirmed row and sends the mail. An existing unconfirmed email re-sends. An existing confirmed email sends nothing. All three cases show the same success message.
- The mail is in the subscriber's locale and links to `URL::temporarySignedRoute(localized name, now()->addDays(7), ['subscription' => id])`.
- **Confirm:** sets `confirmed_at` and shows the confirmed page. An invalid or expired signature shows the expired page with status 403.
- **CTA band:** Exhibit and Register buttons, plus the newsletter form.
